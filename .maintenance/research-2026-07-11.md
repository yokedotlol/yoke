### ⚠️ ACTIONABLE: DMARCbis Published as RFC 9989/9990/9991 (May 20, 2026)

Major email standards update — DMARC moved from Informational (RFC 7489) to **IETF Proposed Standard** (Standards Track). Three new RFCs replace the original:

- **RFC 9989**: Core DMARC protocol
- **RFC 9990**: Aggregate reporting (RUA)
- **RFC 9991**: Failure reporting (RUF)

Key changes relevant to Yoke's email axis scoring:
1. **DNS Tree Walk replaces Public Suffix List** for Organizational Domain determination
2. **Deprecated tags**: `pct=`, `rf=`, `ri=` — receivers MUST ignore them
3. **New tag**: `np=` for non-existent subdomain policy
4. **New tag**: `psd=` for Public Suffix Domain declarations
5. **SPF alignment**: Uses only MAIL FROM, no HELO fallback
6. `v=DMARC1` identifier unchanged — backward compatible

**Recommendation**: Update Yoke's DMARC parsing/scoring to:
- Recognize and report `np=` and `psd=` tags
- Flag deprecated `pct=`/`rf=`/`ri=` tags as informational findings (not errors)
- Reference RFC 9989 instead of RFC 7489 in findings text

### New WIMSE Drafts (June 2026)

Two significant new WIMSE-related drafts appeared since last check:

1. **draft-jiang-wimse-heterogeneous-credential-00** (June 2026) — "Heterogeneous Credential Verification for Workload and Agentic Systems." Addresses how a relying party verifies multiple credential types (WIMSE tokens, OAuth tokens, JWTs, X.509 certs, VCs) received together in a single request from an AI agent. This is a real gap that existing specs individually don't cover.

2. **draft-reece-wimse-cross-org-delegation-00** (June 2026) — "Cross-Organizational Delegation for Workload and Agent Identity." Problem statement for when agents cross organizational boundaries. Argues that none of the existing mechanisms answer all identity questions across org boundaries.

### ⚠️ CRITICAL: Vite CVE-2026-39365

**CVE-2026-39365** affects Vite versions < 6.4.2 (and < 7.3.2). Our version 6.3.5 is affected.

- **Vulnerability**: Arbitrary file read via Vite dev server WebSocket. `server.fs` check not enforced on `fetchModule` method exposed through WebSocket.
- **Severity**: CVSS 8.2 (HIGH) — though practically lower since this only affects dev servers exposed to the network, never production.
- **Impact for Yoke**: LOW — Vite is a devDependency used only for client builds. Never runs in production (CF Workers serve the built assets). However, anyone developing Yoke locally with `--host` flag would be exposed.
- **Fix**: Upgrade `vite` to ≥6.4.2 in `client/package.json`
